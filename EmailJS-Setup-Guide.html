শুরু করার আগে

গুরুত্বপূর্ণ: অ্যাপের সঠিক লগইন ফাইলটি login.html (বড় হাতের LOGIN.html নয়)। এই ফাইলে EmailJS SDK ও বর্তমান Public Key, Service ID এবং Template ID আগে থেকেই যুক্ত আছে। Dashboard-এ এগুলো বদলালে তবেই ফাইলের মানগুলো মিলিয়ে আপডেট করতে হবে।

১. EmailJS অ্যাকাউন্ট ও ইমেইল সার্ভিস

  1. EmailJS-এ অ্যাকাউন্ট খুলে ইমেইল ঠিকানা যাচাই করুন।
  2. Dashboard-এর Email Services থেকে Gmail বা আপনার ব্যবহৃত মেইল সার্ভিস যুক্ত করুন।
  3. অনুমোদিত অ্যাকাউন্ট/সংযোগ প্রক্রিয়া সম্পন্ন করে Service ID সংরক্ষণ করুন।

ইমেইল পাসওয়ার্ড দেবেন না: Gmail-এর “Less Secure Apps” সুবিধা বন্ধ। EmailJS-এ সার্ভিস যুক্ত করার সময় দেখানো অনুমোদিত সাইন-ইন/কানেকশন পদ্ধতি ব্যবহার করুন; কখনো ইমেইল পাসওয়ার্ড বা App Password ওয়েবপেজে লিখবেন না।

২. ইমেইল টেমপ্লেট তৈরি করুন

  1. Email Templates থেকে নতুন Template তৈরি করুন।
  2. To Email ঘরে {{to_email}} এবং Subject ঘরে {{subject}} দিন।
  3. ইমেইলের মূল অংশে নিচের ভেরিয়েবলগুলো রাখুন; এগুলোর নাম login.html থেকে পাঠানো মানের সঙ্গে মিলতে হবে।
প্রিয় ব্যবহারকারী,

আপনার {{type}} যাচাইকরণ কোড: {{verification_code}}

কোডটি লগইন পেজে প্রবেশ করুন।

Template ID সংরক্ষণ করুন। Dashboard-এর Template Test থেকে নিজের ঠিকানায় একটি পরীক্ষামূলক ইমেইল পাঠিয়ে To Email ও ভেরিয়েবলগুলো যাচাই করুন।

৩. অ্যাপের সেটআপ মিলিয়ে দেখুন

বর্তমান login.html EmailJS v3 Browser SDK ব্যবহার করে এবং to_email, subject, type ও verification_code পাঠায়। Dashboard-এ কোনো ID বদলালে ফাইলের সংশ্লিষ্ট মানগুলোর সঙ্গে নতুন ID মেলান:

emailjs.init("YOUR_PUBLIC_KEY");
await emailjs.send(
  "YOUR_SERVICE_ID",
  "YOUR_TEMPLATE_ID",
  templateParams
);

নিরাপত্তা—প্রকাশের আগে ঠিক করুন: Browser-এ ব্যবহৃত Public Key ব্যবহারকারীরা দেখতে পারেন—এটি গোপন key নয়। EmailJS-এর অনুমোদিত domain/origin সীমাবদ্ধ করুন; Private Key বা ইমেইল পাসওয়ার্ড HTML/JavaScript-এ রাখবেন না। বর্তমান login.html-এ OTP ও registration password localStorage-এ রাখা হয়, OTP মেয়াদোত্তীর্ণ হওয়ার সময় যাচাই হয় না, এবং যাচাই browser-এই হয়। তাই ইমেইলের টেমপ্লেটে “১৫ মিনিটে মেয়াদ শেষ” লিখবেন না—এটি বর্তমানে enforce করা নেই। প্রকৃত নিরাপত্তার জন্য OTP তৈরি/যাচাই server-side করুন এবং password নিরাপদ authentication service (যেমন Firebase Authentication) দিয়ে সামলান।

৪. ওয়েব ও ফোনে পরীক্ষা করুন

  1. Dashboard-এ Template Test সফল হয়েছে নিশ্চিত করুন।
  2. ওয়েবসাইটটি HTTPS বা localhost-এ চালু করে লগইন পেজ খুলুন। সরাসরি file:// থেকে খোলার বদলে ওয়েব সার্ভার ব্যবহার করুন।
  3. নিজের নিয়ন্ত্রিত ইমেইল ঠিকানা দিয়ে রেজিস্ট্রেশন/পাসওয়ার্ড রিসেট পরীক্ষা করুন; Inbox ও Spam/Junk—দুটিই দেখুন।
  4. Android Chrome এবং কম্পিউটারের Chrome/Edge/Firefox-এ পেজটি খুলে লেখা, বাটন ও কোড ব্লক স্ক্রিনের বাইরে যাচ্ছে কি না দেখুন।
  5. ইমেইল না এলে Browser Console এবং EmailJS Dashboard-এর error/activity log দেখুন।

বিকল্প পদ্ধতি ও সমস্যা সমাধান

  • To Email ফাঁকা/ভুল: Template-এর To Email ঘরে {{to_email}} আছে কি না দেখুন।
  • Template variable error: {{verification_code}}, {{subject}} ও {{type}} বানান হুবহু মিলিয়ে নিন।
  • অনুমতি বা quota error: EmailJS service connection, অনুমোদিত domain এবং account-এর বর্তমান quota যাচাই করুন।
  • Network error: ইন্টারনেট সংযোগ, browser extension এবং Content Security Policy/hosting configuration পরীক্ষা করুন।

mailto: ব্যবহার করলে ইমেইল স্বয়ংক্রিয়ভাবে পাঠানো হয় না—ব্যবহারকারীর ইমেইল অ্যাপ খুলে যায়। তাই এটি verification-code পাঠানোর বিকল্প নয়।
